# Task 20 — Betting layer

## Built

- `src/ncaa_quant/betting/devig.py` — proportional (default), multiplicative
  (power), and Shin de-vig; American/decimal helpers; two-way wrappers.
- `src/ncaa_quant/betting/edges.py` — best-book line shopping, edge =
  `p_model − p_market_devigged`, EV at the actual American price.
- `src/ncaa_quant/betting/kelly.py` — full Kelly (reporting only) and
  fractional Kelly staking with hard-coded caps, weekly/team exposure limits.
- `src/ncaa_quant/betting/filters.py` — §12 filters driven by `BettingConfig`
  / `configs/betting.yaml` defaults.
- `src/ncaa_quant/betting/clv.py` — store line-at-recommendation + close;
  CLV in proportionally de-vigged probability space; weekly settlement report.
- Tests: `tests/unit/test_betting.py`.

## Default de-vig: proportional — why

DESIGN §2.7 defines the CLV label as proportionally de-vigged implied
probabilities. §12 edge math compares against de-vigged market probs in the
same space. Proportional (`p_i = q_i / Σq`) is therefore the production
default so CLV, edge, and market baselines stay consistent.

Multiplicative here means the **power method** (`Σ q_i^c = 1`), which is
distinct from proportional. Shin (1993) uses the standard
`q_i² / Σq` inversion. Method is selected via the `method=` argument
(`DEFAULT_DEVIG_METHOD = "proportional"`).

## Hard staking caps (enforced in code)

Module constants in `kelly.py`:

- `HARD_MAX_STAKE_PCT = 0.015` — stake never exceeds 1.5% of bankroll.
- `HARD_MAX_KELLY_FRACTION = 0.25` — staking never uses full Kelly; config
  `kelly_fraction` can only tighten below 25%.

`full_kelly()` remains available for reporting. `recommended_stake()` always
applies `min(config, hard)` so raising `max_stake_pct` or `kelly_fraction` in
config cannot bypass the ceilings
(`test_staking_cap_cannot_be_bypassed_by_configuration`).

## Decisions / ambiguities

1. **`devig_method` not in `BettingConfig`.** Task says selectable in config,
   but adding a YAML field requires editing `config.py` (out of
   `src/ncaa_quant/betting/` scope). Selectable via function argument; wire
   into YAML/`BettingConfig` in a follow-up if desired.
2. **“Multiplicative” naming.** Spec lists proportional vs multiplicative as
   distinct. Interpreted multiplicative as the power method (not a synonym for
   proportional). Documented above.
3. **Bowl / exposure placeholders.** Still using Task-2 PLACEHOLDER defaults
   from `configs/betting.yaml` (`bowl_edge_multiplier=1.5`,
   `max_bets_per_week=10`, `max_exposure_per_team=0.05`,
   `max_weekly_exposure=0.10`, `min_model_market_agreement=7.0` points).
4. **CLV close definition.** Each `RecommendationRecord` stores which close
   definition will be used (`odds_api_consensus` | `cfbd_close`) per §2.7 /
   §3.4; settlement reports echo it. Caller supplies the close American prices.
