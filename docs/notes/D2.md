## Finding: does the mapping layer earn its complexity?

**How much MAE does the feature stack + GBDT buy over L1?**

On this canonical clean set, LightGBM / published μ MAE = **13.731** vs Elo-OLS
L1 = **14.903** → gap **1.17 points**. That is larger than D1’s 0.2–0.5 estimate
because D1’s L1 was OLS on Stage-1 rating differential (already a strong single
feature, smoke L1≈14.02 → NNLS≈13.50, gap≈0.52). Against a weaker Elo-based L1
proxy the stack looks better; against a proper Stage-1 L1 the D1-scale gap is
the right prior.

**Plain statement:** the mapping layer buys on the order of **half a point to
about one point of MAE** over a competent single-feature OLS, not a
transformative lift. Complexity is only weakly justified by point MAE alone;
distributional / market metrics (D3–D4) have to carry the rest of the case.

## Part 1 — silent failure made impossible

1. `BasePredictor._unfitted_predictions` **deleted**. Unfitted `predict()` raises
   `NotFittedError`. Quantile head override removed.
2. Walk-forward quality gate (`assert_prediction_quality_gate`) fails loudly on
   scored rows when `zero_mu_rate > 0.001`, any `(season,week)` block with n≥2
   has `SD(μ)=0`, any null μ, or `n_train_games < min_train_games`.
3. Prediction tables carry `run_kind ∈ {smoke, backtest, production}` and
   `n_train_games`. Reporter (`assert_not_smoke_for_headline_metrics`) refuses
   headline metrics from smoke runs.
4. Tests: unfitted head raises; planted zero-inflated table trips gate;
   smoke-tagged table refused by reporter.

The archived full table fails the gate for the exact D1 poison (weeks 1–4 of
2019 emit μ=0 via the deleted cold-start path). After removing that block, the
gate passes — confirming the gate detects the failure mode and that the
remainder of task23_fundamental is structurally clean.

## Part 2 — NNLS wired

`ProductionEnsemblePredictor._set_weights` now calls `fit_nnls_stack` on the
time-ordered OOF member matrix (`lgbm_mu_margin`, `enet_mu_margin`). The
0.5/0.5 hardcode is gone. Degenerate OOF raises unless
`nnls_equal_weight_fallback: true` is set explicitly in config; the fallback is
stamped on the prediction table (`nnls_fallback`) and logged in
`nnls_fold_reports`.
