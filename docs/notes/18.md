# Task 18 — Optuna hyperparameter optimization

## Built

- `src/ncaa_quant/models/hpo.py` — DESIGN §6 HPO framework:
  - Persistent Optuna studies (SQLite), TPE (`multivariate=True`), Hyperband pruner
  - Walk-forward objective: mean loss over last 3 validation seasons (MSE / pinball / Gaussian CRPS)
  - `HPOTrainWindow` restricted data handle (nested isolation)

- Tests: `tests/unit/test_hpo.py`

## Nested isolation — structural guarantee

Outer-test rows are **dropped at construction** and never stored. Access raises:

```python
# HPOTrainWindow.from_frames(... train_seasons=..., outer_test_seasons=...)
#   → only train_seasons rows retained in _slices
#   → outer_test_seasons recorded in _forbidden_seasons

def get(self, season: int) -> SeasonSlice:
    if s in self._forbidden_seasons:
        raise NestedIsolationError(...)   # outer test
    if s not in self._slices:
        raise NestedIsolationError(...)   # outside window
    return self._slices[s]
```

`WalkForwardObjective` closes only over an `HPOTrainWindow`. The objective is
structurally incapable of reading outer-test seasons: those rows do not exist
on the handle, and any explicit `window.get(outer_test_season)` raises.

## Quarantine regularization tiebreak (codified)

When quarantine ranking of the top-5 study configs disagrees with Optuna order,
select the more regularized config by lexicographic sort key (lower wins):

1. **higher** `min_child_samples`
2. then **lower** `num_leaves`
3. then **higher** `lambda_l2` (also accepts `reg_lambda`)

## Decisions / ambiguities

1. **No `optuna-integration`.** Not in `pyproject.toml`; implemented
   `_LGBMPruningCallback` / `_FoldAwarePruningCallback` analogs instead.
2. **Trial fits bypass Task-17 head classes.** Direct LightGBM/XGB/CatBoost/
   ElasticNet/NGBoost fits inside the objective so early stopping (200 rounds)
   and pruning callbacks work. Best params map back via
   `params_to_head_train_config` → `HeadTrainConfig`.
3. **Quarantine vs outer test.** Quarantine must be outside the HPO train
   window **and** not an outer test season (would violate nesting). Typical
   layout: drop one inner season (e.g. COVID 2020) as quarantine.
4. **Hyperband + per-round reporting** is aggressive on small synthetic data
   (90/100 pruned in the acceptance study). Production studies with more rows
   should prune less extremely; fold-level reporting remains available via
   non-LGBM heads.
5. **Default LGBM `n_jobs=4`** per §6; tests / acceptance used `n_jobs=1` for
   Windows process-pool stability.
