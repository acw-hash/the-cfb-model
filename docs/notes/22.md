# Task 22 — MLflow, registry, promotion, rollback

## Built

- `src/ncaa_quant/registry/` — model registry + MLflow integration:
  - `stages.py` — `candidate → challenger → champion → archived`
  - `manifest.py` — `RunManifest` binding git SHA + DVC hash + config hash +
    seed manifest + lockfile hash (§8.8)
  - `tracking.py` — `TrackingSession`, `log_training_run`, `log_evaluation_run`
    (params, per-season metrics, artifacts, manifest)
  - `store.py` — filesystem index + artifact dirs; MLflow stage tags (best-effort)
  - `promote.py` — pre-registered gate (CRPS + log-loss + CLV, paired block
    bootstrap p < 0.10) + calibration + leakage; archive-on-fail with comparison
    report; `--force` override records (non-bypassable from config)
  - `resolve.py` — inference always resolves `champion` (raises `NoChampionError`)
  - `cli.py` / `__main__.py` — `python -m ncaa_quant.registry {promote,rollback,resolve-champion}`
- Tests: `tests/unit/test_registry.py`

## Decisions / ambiguities

1. **Local index is source of truth for custom stages.** MLflow 2.x native stages
   are Staging/Production/Archived; our four-stage lifecycle lives in
   `registry_index.json` under the registry root, with MLflow run tags
   (`registry.stage`, `registry.version`) synced best-effort.
2. **Tracking helpers, not wired into models/evaluation modules.** Task scope is
   `registry/` only. Training/evaluation call `log_training_run` /
   `log_evaluation_run` / `TrackingSession` when those pipelines are connected
   (Task 23–24). No edits to `models/` or `evaluation/`.
3. **CLI lives in-package.** Rollback CLI is `python -m ncaa_quant.registry`
   rather than extending `ncaa_quant.cli` / Makefile (out of scope). Flag if you
   want it wired into the main Typer app.
4. **Cold-start (no incumbent).** Metric significance is skipped; calibration +
   leakage still required. First champion is pinned via the same `promote()` path.
5. **Paired p-value.** One-sided block bootstrap on the advantage series
   (champ−cand for lower-is-better; cand−champ for CLV) with +1 correction.
   Promote requires advantage > 0 and p < 0.10 on **all three** metrics.
6. **Leakage gate** is a boolean input from the caller (leakage suite). No
   leakage runner lives in `registry/`.
7. **Calibration band** defaults to pipeline §14 `[0.85, 1.15]`; overridable per
   call but there is **no** config flag to skip the gate.
