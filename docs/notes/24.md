### Infrastructure

- **Idempotency** — `PartitionKey(source, partition)` ledger at
  `data/pipeline_state/idempotency.json`; re-runs skip completed partitions.
- **Dead-letter queue** — poisoned partitions appended under
  `data/pipeline_state/dead_letter/`.
- **Retries** — tenacity 3× exponential backoff on `@task` wrappers.
- **STALE mode** — on ingest failure, `predict_publish` uses last-good raw
  snapshot, stamps every prediction `STALE(source, age)`, sets
  `BetCandidate.is_stale=True`; Task 20 filter suppresses bets
  (`FilterReason.STALE_INPUTS`).
- **Notifications** — ntfy/Telegram via `pipelines/notifications.py`;
  provider configured in `configs/pipeline.yaml` (`notifications.provider`);
  tokens in `.env` (`NTFY_AUTH_TOKEN`, `TELEGRAM_BOT_TOKEN`).
- **Human gates** — `pipelines/gates.py`: promotion requires gate pass +
  manual approve (or explicit `--force` from registry); bet confirmation shows
  line-at-recommendation and voids when line moved past
  `pipeline.bet_line_move_void_points` (§16 item 3) or inputs are STALE.
- **API-key scrub** — `pipelines/metadata.py` scans raw archives; runbook in
  `docs/runbooks/api_key_scrub.md`.

## Decisions / ambiguities

1. **Prefect parameter schema** — injectable callables (`predict_fn`, `notifier`,
   etc.) cannot appear on `@flow`/`@task` signatures (Prefect pydantic schema
   rejects Protocol/Callable). Production flows expose serializable params only;
   test helpers call `run_*` / `execute_*` functions directly.
2. **Weekly/retrain bodies** — default implementations are thin orchestration
   stubs calling underlying modules where they exist (`run_cfbd_incremental`,
   `run_quality`, registry promotion gate). Full production wiring of ratings
   feature materialization into flows deferred to when CLI `ratings`/`train`
   paths are connected — flows are structurally complete and idempotent now.
3. **`notifications.provider: "null"`** — YAML must quote `"null"`; bare `null`
   loads as Python `None` and breaks pydantic validation.
4. **T−6h / T−1h refresh** — `RefreshKind.T_MINUS_6H` / `T_MINUS_1H` defined;
   separate Prefect deployments for kickoff-relative schedules left to operator
   wiring (requires game-time parameterization not expressible as static cron).
