## Decisions / ambiguities

1. **`pit_audit` location.** DESIGN §11 lists `quality/pit_audit.py`, but Task 7
   already owns that module for ingestion temporal contracts. Feature
   recomputation audit lives at `features/pit_audit.py` so the two concerns
   stay separate.
2. **Registry empty at Task 9.** No production builders yet; default YAML is
   `features: []`. Tests use fixture YAML / in-memory `FeatureSpec`s.
3. **Output contract.** Builder frames use columns `entity_id`, `as_of`,
   `value` (+ `is_missing` when `null_policy=indicator`). Materializer adds
   `season`, `week`, `feature`.
4. **Skip semantics.** Skip when `meta.json` exists, `spec_hash` matches the
   current registry entry, and `content_hash` matches on-disk parquet bytes.
   `force=True` recomputes.
5. **DVC not a Python dep.** `dvc_add_partition(..., run=False)` returns argv;
   operators run `dvc` on PATH (documented in `docs/feature_store.md`).
6. **Dependencies.** Feature-to-feature edges participate in the topo sort;
   `raw:<table>` deps are leaves (not ordered).
7. **DuckDB ASOF.** Strict `right.ts < as_of` via DuckDB `ASOF LEFT JOIN`,
   parallel to the pandas helper for store-level queries.

## Prior-task gap (not patched)

`ncaa_quant.data.asof.as_of_join` with a multi-entity right frame whose
`event_time` is not *globally* monotonic raises pandas
`ValueError: right keys must be sorted` even after sorting by
`(entity_id, event_time)`. Existing Task 3 tests only cover single-entity (or
identical timestamps). Builders should call `as_of_join` per entity group or
use `filter_event_time` until Task 3 is fixed — **not patched here**.
